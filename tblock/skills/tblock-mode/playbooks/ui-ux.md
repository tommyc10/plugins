### UI/UX

**You own the experience. Plan, build, prove.**

1. Look for a DESIGN.md file or the equivalent to understand the look and feel of the project, if no such a file exist look at the pure css and use importance-is-obvious defaults and say so
2. List every state the ui element can be in
3. Name the primary action and the order of events
4. Build from existing tokens and componenets. Smallest change (laziness-protocol),
5. Apply the **emil-design-eng** skill for component details and polish. If the UI has scope for motion, use the **animate** skill aswell
6. Prove it in a real browser, every state
7. Log the decisions


**Reply** a explaintion for each state, the choices made, why and anything left open
